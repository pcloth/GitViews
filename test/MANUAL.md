# Git Views 人工验收

以下项目需要真实 VS Code 窗口；自动化单元测试通过不代表这些平台已经人工验收。

1. 执行 `pnpm install --frozen-lockfile`、`pnpm check`、`pnpm test`，按 F5 启动开发宿主，打开包含分支与合并提交的仓库。
2. 点击活动栏 Git Views；确认历史在主侧栏显示，Ctrl+B（macOS Cmd+B）显隐侧栏，编辑区不打开历史标签。调整侧栏宽度和详情分隔条。
3. 滚动超过 200 个提交，确认加载更多且拓扑连接连续。筛选分支、作者、提交说明；用键盘上下键选择提交。
4. 点击提交和变更文件，确认原生 diff 的左侧为所选父提交、右侧为目标提交。分别检查新增、删除、重命名、根提交和二进制文件。对合并提交切换父提交。
5. 设置比较起点，选择另一提交并比较；确认展示两个快照间的变更。通过命令面板输入两个 SHA 重复验证。
6. 打开跟踪文件，移动光标，悬停行末信息。插入未保存行，确认新行显示“尚未提交”，原有行仍映射到正确提交。编辑、撤销及保存后重复验证。
7. 从 blame 悬停点击“在 Git Views 中查看”，确认定位正确；点击“查看此文件差异”，确认打开当时路径对应的 diff，包含后来重命名的文件。
   在 Windows 盘符路径，以及包含中文、空格、百分号或括号的仓库路径中重复验证，确认不会误报“仓库已关闭”。
8. 内置终端运行 `git log`、`git log --oneline`、`git log --graph --oneline --all`，按终端提示点击 SHA；确认展开侧栏、选中目标、展示文件列表，并且不自动打开第一个文件。对于尚未加载的旧提交检查“提交及祖先”和“返回”。
9. 多根工作区加入两个仓库，在各仓库终端点击 SHA，确认仓库选择正确；禁用 shell integration 后检查回退和有歧义时的仓库选择。无效 SHA 应出现简短提示。
10. 在终端执行普通 Git 提交、分支变更后确认侧栏刷新，选择与滚动位置保留；隐藏侧栏后执行 Git 操作，重新打开时确认刷新。
11. 检查浅色、深色、高对比度主题，以及中文/英文界面、无仓库/空仓库状态。启用内置行内 blame，确认一次性冲突提示仅在点击关闭按钮后修改设置。
12. 在 Windows 本地、Remote WSL、Remote SSH 分别安装或启动扩展重复步骤 2、6、8。macOS 另检查 Cmd+点击和 Cmd+B。
13. 执行 `pnpm package`，在独立 VS Code 窗口从生成的 VSIX 安装，重复打开侧栏、终端跳转与 diff。确认包不依赖开发目录里的 node_modules。
